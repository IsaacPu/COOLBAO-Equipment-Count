# COOLBAO｜面向消防报警行业的建筑数图 Workflow 产品

### 把图纸里的设备信息，变成可核对、可交付的点位表。

面向需要从工程图纸统计设备的技术人员，将 CAD 图纸中的设备信息整理为按楼栋、楼层组织的点位表，辅助完成统计、复核与表格交付。

这是我在任职期间推进的企业项目实践。我的工作覆盖**前期 PoC、真实人工数图学习、设备配置与统计规则梳理、与 DXF 团队共同制定后续方案，以及已有能力整合与交接**。

## 为什么做这个产品

人工数图需要不断判断：图上的符号代表什么设备、属于哪个系统、标准层怎样展开、哪些设备有特殊配置，以及最终应该填进表格的哪一项。

我希望将其中规则明确、可以重复执行的步骤交给软件，并为需要技术人员判断的部分保留来源和复核依据。

## 使用前后的流程变化

| 工作环节 | 人工处理方式 | 软件辅助后的流程 |
| --- | --- | --- |
| 查找设备 | 按设备类别反复查看图纸、记录位置 | 从 CAD 结构信息中提取设备候选，集中查看 |
| 计算楼层数量 | 人工记录适用楼层、展开标准层并累加 | 按明确的楼层集合试算，范围疑点单列 |
| 检查差异 | 在图纸、手工记录和表格之间来回查找 | 结合对象来源、楼层和待核对项复核 |
| 整理交付表 | 按不同表格格式整理与转填 | 从同一统计版本选择客户表或泰和安表导出 |

收益先按流程变化表达；目前不报告未经完整测量的节省工时、准确率或 ROI 百分比。

## 我的贡献

### 1. 完成前期 PoC，验证产品闭环

围绕真实数图需求拆解任务，借助 AI 编码工具推进原型研发，形成图纸输入、结构化解析、报警七类试算到逐层表格交付的前期 PoC，用原型识别可行性、流程问题和需要明确的业务规则。

### 2. 深入人工数图，理解结果背后的判断

参与真实人工数图学习，理解设备配置、图纸识读、设备归属、标准层及统计口径。重点弄清楚：**业务上为什么这样数，软件结果应怎样核对，什么情况需要技术人员判断。**

### 3. 将业务认知转化为产品要求

把学习和核对中发现的问题，转为设备范围、楼层处理、异常状态、人工复核及表格交付要求，并参与真实图疑点判断与结果对照，让规则能够被实现、讨论和验证。

### 4. 与 DXF 团队共同制定后续方案

结合 PoC 和真实数图学习中发现的问题，与 DXF 团队共同制定后续方案，为下一阶段提供业务依据。**下一重点实施阶段尚未开展，方案准备与实际落地分别记录。**

### 5. 推动已有能力整合与交接

在同事已有网站和基础框架上，推动接入对象追溯、图框与楼层规则、人工复核及两类表格导出等能力，并整理已有实现、已知问题和接手材料。

协作分工：我负责前期 PoC 的产品推进、业务规则探索及能力整合；同事负责既有网站与基础业务框架；AI 编码工具协助工程实现。

## Features｜已实现的主要能力

| 能力 | 作用 |
| --- | --- |
| CAD 结构化解析 | 提取图块、属性、文字、位置与引用关系，形成统计依据 |
| 报警七类试算 | 在当前规则范围内统计感烟、感温、手报、消报、声光、扬声器和电话分机 |
| 图框与标准层处理 | 关联统计范围，展开明确楼层；未知与冲突保留待核对 |
| 来源追溯与人工复核 | 查看对象依据、处理疑点并保留裁决记录 |
| 两类同源导出 | 从同一统计版本生成客户 XLSX 或泰和安点位表 XLS |

能力已实现不代表所有新图都能准确处理。当前自动范围为报警七类，其他设备与未支持范围需要另行验证。

## 关键产品判断

- **先收敛试点范围：**从报警七类入手，建立可以核对的小闭环，再依据实际问题讨论扩展。
- **简化操作，保留判断依据：**主流程围绕选图、进度、结果、核对与下载组织，后台保留来源和异常。
- **明确人机边界：**规则明确的部分交给软件；语义冲突、未知范围和特殊配置保留人工判断。
- **复用团队已有成果：**将可复用能力接入既有系统，围绕共同交付目标推进整合。
